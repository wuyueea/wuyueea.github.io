前言

本篇博客是我的第一篇正式博客，具有从0到1的里程碑式意义。关于写博客的初衷，主要是上大学开始迷上电脑后，就致力于寻找各种资源（好用的软件、实用的功能与资源网站），在这个过程中也接触到了一系列awesome的技术，对于感兴趣的就进一步学习研究，但学会后如何生活中没有一定频率的使用就会让这类记忆在自己的脑子里积灰，在一定程度上产生了一点遗忘焦虑（虽然大部分很容易捡起来，但对于深度技术就不好说了）。另外，在很久之前，自从在朋友圈看到一篇有关记录生活的动态后，从此就迸发出了一种对记录的狂热吧，也因此在去年开始每天坚持写一篇简单的回忆日记，到现在的写博客也算是一种延伸。总的来说，我写博客主要就是为了记录正式学习以及整合一些资源吧。
说完了写博客的初衷，现在就是讨论建站的初衷，在学习建站的过程中看了网络上的很多文章，除了具体的技术教程，有些还说到“每一个程序员都梦想拥有自己的个人网站”，虽然我也许不算一个彻底的程序员，我一般也觉得我算是个极客，热衷于各种技术捣鼓，之前也想过就把自己的文章放本地得了，但是接触到了很多个人网站后，我羡慕了，我也想拥有，所以就促成了这个网站、这篇文章。
初衷终于全部写完了（第一篇博客文章没什么经验，实在太话痨了，哈哈哈），直接进入正题。在网上看了很多教程后，我自己还是拿不定主意，也许是第一次的谨慎吧。最后问的deepseek，由于我看的Hexo+GitHub Pages教程最多，所以直接将其作为参考项，要求分析这个组合的可行性和优缺点，并针对推荐一些可能的更优选择。最后还是因为这个方案的“零成本”（正好戳中我这个极致白嫖党）以及对我而言没有难以接受的缺点而最终尘埃落定。

关联 GitHub 并部署

本地看没什么问题后，就可以正式部署到GitHub Pages上了。
（1）创建GitHub仓库：登录GitHub账号，新建一个仓库（Repository）。仓库名称必须严格遵守你的GitHub用户名.github.io的格式，比如你的用户名是john，仓库名就要是john.github.io。这个命名一旦出错，后面就无法正常访问了，另外提一嘴，你的用户名就是你的账户名，注意是账户而不是昵称，设置里面可以看。为了后续推送顺利，创建新仓库时，不要勾选“Add a README file”等初始化选项，我们要的是一个完全空白的仓库。
